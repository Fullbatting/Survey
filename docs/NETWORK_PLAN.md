# 접속 방식 검토와 다음 단계

설문 링크·QR을 응답자 휴대폰에서 여는 방법에 대한 검토 내용입니다. (2026-10-15)

## 1. 현재 동작

- 서버는 설문마다 고유 링크(`/f/<slug>`)와 QR 코드를 만듭니다.
- `HOST=0.0.0.0`이면 서버가 PC의 내부 IPv4를 자동으로 찾아 링크·QR에 사용합니다. 같은 Wi-Fi의 기기에서만 열립니다.
- `HOST=127.0.0.1`(현재 기본값)이면 링크·QR은 서버 PC에서만 열립니다.
- `HOST=0.0.0.0`이면 같은 Wi-Fi의 다른 기기도 관리자 로그인 화면에 접근할 수 있습니다. 기본 비밀번호(`change-this-password`)는 공개된 값이므로 반드시 바꿔야 합니다.

## 2. 다른 인터넷 환경(LTE·5G, 다른 Wi-Fi)에서 열기

QR은 주소를 담을 뿐이므로, 주소가 인터넷에서 접속 가능해야 합니다.

| 방법 | 처음 한 번 | 매번 할 일 | 주소 | 비고 |
|---|---|---|---|---|
| 공유기 포트 포워딩 + DDNS | 포워딩, 내부 IP 고정, DDNS 등록 | 서버 실행 | 고정 | 무료, HTTPS 없음, 통신사 차단 가능 |
| Cloudflare 고정 터널 | 계정·도메인, 터널 등록, 서비스 설치 | 서버 실행 | 고정 | 도메인 비용, HTTPS 자동 |
| ngrok 고정 주소 | 가입, 무료 고정 주소 발급 | 서버(+터널) 실행 | 고정 | 무료 요금제 제한 |
| Cloudflare 임시 터널 | 프로그램 설치 | 실행할 때마다 주소 변경 | 변동 | 테스트용 |
| 클라우드 배포 | 서버 구성, DB 전환 | 없음 | 고정 | PC 불필요, 비용·운영 부담 |

인터넷에 공개할 경우 필요한 것: 외부 주소(`PUBLIC_URL`) 설정, 외부 요청의 관리자 화면 차단, 기본 비밀번호로 실행 금지.

## 3. 검토 중인 방향: 인터넷 없이 서버 PC 중심 운영 (진료실 예시)

1. 진료실에 QR을 비치합니다.
2. 환자가 Wi-Fi에 연결한 뒤 설문 QR을 스캔해 응답합니다.
3. 의료진이 서버 PC의 결과 화면에서 확인합니다.

조건: 환자 휴대폰이 서버 PC와 같은 Wi-Fi에 있어야 합니다(LTE로는 접속 불가).

네트워크 구성:

- 설문 전용 공유기(권장): 서버 PC와 환자 휴대폰만 연결합니다. 인터넷·병원 내부망(EMR)과 분리됩니다.
- 기존 손님용 Wi-Fi: 서버 PC도 같은 Wi-Fi에 있어야 하며, 기기 간 통신 차단(AP 격리) 여부를 확인해야 합니다.
- 병원 내부망에 환자 기기를 연결하는 것은 피합니다.

구현 후보:

1. 관리자 화면(로그인·편집·결과)은 서버 PC에서만 열고, 다른 기기에는 설문 페이지만 제공
2. 진료실 비치용 A4 인쇄 페이지 (Wi-Fi 접속 QR + 설문 QR + 안내문, Wi-Fi 정보는 `runserver.bat`에서 설정)
3. `HOST` 기본값을 `0.0.0.0`으로 변경 (1번 적용 후)

현장 1회 설정:

- 공유기에서 서버 PC 내부 IP 고정(DHCP 예약) — IP가 바뀌면 인쇄한 QR이 열리지 않음
- 서버 PC 절전 모드 해제
- 첫 실행 시 Windows 방화벽에서 개인 네트워크 허용

개인정보: 환자 설문에 식별 정보나 건강 정보가 포함되면 민감정보에 해당할 수 있습니다. 가능하면 익명으로 구성하고, 필요한 경우 동의 문구와 보관 정책을 별도로 검토합니다(법률 검토 필요).

## 4. 결정 대기

- [ ] 운영 방식: 서버 PC 중심(3장) / 인터넷 공개(2장)
- [ ] 3장 구현 후보 1~3 진행 여부
- [ ] 인쇄 페이지에 Wi-Fi 접속 QR 포함 여부
- [ ] 네트워크: 설문 전용 공유기 / 기존 손님용 Wi-Fi

## 5. 알려진 미해결 사항

- 로그인 화면과 응답 제출 화면의 일부 인라인 스타일이 CSP(`style-src 'self'`)에 막혀 적용되지 않습니다(예: 버튼 전체 너비).
- 디자인 시안의 질문 드래그 손잡이는 구현하지 않았습니다. 순서는 화살표 버튼으로 바꿉니다.
